# 首次配置

本文用于发行包首次落地。配置要求由 Satsuma 发行物和 Schema 定义；使用者 AI 可以协助发现环境、填写模板
和执行验证，但不能自行决定 VM 范围、猜测快照或代替用户授权管理员操作。

## 职责边界

| 参与方 | 负责事项 |
|---|---|
| Satsuma 发行物 | 提供配置模板、Schema、字段说明、安装脚本和验证命令 |
| 使用者 AI | 只读发现 Host 环境，汇总缺失信息，按模板生成本机配置 |
| 用户 | 选择实验 VM、基础快照和 Shared Folder，确认可能丢失 Guest 状态的操作 |
| Satsuma CLI | 校验配置、VMware、共享目录、Agent presence 和文件往返通道 |

## 需要确认的信息

Host 侧：

- `vmrun.exe` 的绝对路径；
- Host 归档目录和 Shared Folder 对应的本机目录；
- 每台实验 VM 的稳定 ID、VMX 绝对路径和期望 Agent 版本；
- 每台 VM 的只读基础快照，以及 Satsuma 快照前缀和数量上限。

Guest 侧：

- 与 Host 配置一致的实验室 ID 和 VM ID；
- Guest 看到的 Shared Folder UNC 路径；
- VMware Tools 已安装并运行；
- 可使用管理员权限安装 LocalSystem Agent Service。

VM、VMX 和基础快照属于用户授权边界。AI 可以读取本机已有路径和命令位置，但无法确认的值必须列为待确认，
不得使用模板占位值继续安装。

## 生成配置

在发行目录使用 [Host 配置模板](../config/lab.template.json) 和
[Agent 配置模板](../config/agent.template.json)：

```powershell
Copy-Item config\lab.template.json config\lab.local.json
Copy-Item config\agent.template.json config\client.agent.json
```

填写 `config/lab.local.json` 中所有 `REQUIRED` 和 `replace_with` 值。每台 VM 都需要一份独立的
`config/<vm-id>.agent.json`；其中 `lab_id`、`vm_id` 和 `agent_version` 必须与 Host 配置对应，`shared_root`
必须是该 Guest 实际可访问的 UNC 路径。

多 VM 实验需要在 `config/lab.local.json` 的 `vms` 中逐台声明，并为每台 VM 生成 Agent 配置。不要让多台正在运行
的 Agent 使用同一个 `vm_id`。

## 安装 Agent

为目标 VM 在 Shared Folder 根目录准备 `satsuma-bootstrap`，放入：

- `bin/SatsumaVM.exe`；
- `scripts/install-agent.ps1`；
- 该 VM 的 Agent 配置，并重命名为 `agent.json`。

在 Guest 管理员 PowerShell 中运行共享目录里的安装脚本。脚本会把文件安装到固定本机目录并注册 Windows
Service；发行包自身仍是便携目录，不需要在 Host 安装。

## 首次验收

Agent 安装后，在 Host 执行：

```powershell
bin\SatsumaHost.exe check --config config\lab.local.json --timeout-seconds 180
```

只有顶层 `status` 为 `ready` 才能发布业务任务。失败时按 `checks` 和 `agents` 字段处理配置、VMware Tools、
Shared Folder 或 Agent 问题；不得仅因为 VM 能启动就宣称环境已经可用。
