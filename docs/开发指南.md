# 开发指南

## 工具链

- Windows 10/11 x64。
- Visual Studio 2022，安装 Desktop development with C++ 和 Windows 10/11 SDK。
- CMake 3.25 或更高版本。
- Git；首次配置且本机没有包时需要访问 GitHub 获取固定版本的 `nlohmann/json`。
- PowerShell 7 仅用于真实 VMware 故障恢复脚本测试；普通构建仍兼容系统 `powershell.exe`。

项目使用 C++20 和静态 MSVC Runtime。当前不支持非 Windows 平台，配置阶段会直接拒绝。

## 构建与测试

```powershell
cmake --preset windows-default
cmake --build --preset windows-debug --parallel
ctest --preset windows-debug
cmake --build --preset windows-release --parallel
ctest --preset windows-release
```

Debug 与 Release 共用 `build/windows-default` 多配置目录。默认测试不操作真实 VMware，只使用临时本地状态
目录、Fake `vmrun`、inproc VMCI 通道和专用测试进程。

测试层次：

- 核心：配置、路径、JSON 原子写入、SHA-256、任务、协议和 claim 模型。
- VM：claim 续租、Job Object、交互用户、Service、自更新和故障隔离。
- Host：运行发布、报告、取消、保留、更新发布和 VMware Provider。
- 集成：单 VM VMCI 流、多 VM 生命周期、安装脚本和示例应用。
- Schema：本地 CTest 使用固定版本的 jsoncons 执行 Draft 2020-12 示例校验，并检查全部 Schema 文档可解析；
  CI 额外执行 metaschema 校验。

修改 VMCI 协议、Controller、Agent 或 Service 时应运行完整 Debug/Release 测试。只改文档时至少运行 Schema
检查和 `git diff --check`。

## 发行目录与打包

生成展开版发行目录和 ZIP：

```powershell
cmake --build --preset windows-release --target SatsumaPackage
```

产物位于根目录 `output/SatsumaTestLab-<version>-windows-x64/` 和同名 ZIP，不会向系统安装文件。该目标使用
PowerShell `Compress-Archive` 写入 UTF-8 文件名标志，避免 CPack ZIP 在中文 Windows 上把中文文件名写成
无编码声明的本地代码页字节。

发行物只包含 Host/VM 生产二进制、待填写配置模板、任务示例、安装脚本、Schema 和公开文档。测试夹具、
Fake `vmrun`、真实故障注入脚本和已填写的本机配置不进入发布包。

## 代码结构

```text
include/satsuma/core/   公共核心模型与 VMCI 协议
src/core/               配置、任务、JSON、路径、哈希、claim、更新模型
src/host/               Controller、诊断、生命周期编排和 CLI
src/vm/                 Agent、Service、进程执行、claim 事务和自更新
src/vmware/             vmrun Provider
schemas/                JSON Schema Draft 2020-12
config/                 Host 与 Agent 发行配置模板
scripts/                Guest 安装脚本
tests/                  单元、集成与显式真实 VMware 验收
```

`SatsumaCore` 不依赖 Host/VM 具体实现；`SatsumaHostLib` 和 `SatsumaVmLib` 分别承载生产逻辑。测试专用 VM
库只把三个测试宏集中编译一次，避免每个测试目标重复编译同一批生产源码。

## 变更规则

- 现有文本保持 UTF-8 和 LF；`scripts/install-agent.ps1` 按 `.editorconfig` 保持 UTF-8 BOM。
- 不批量格式化无关文件。MSVC 使用 `/W4 /permissive- /utf-8`，新增警告应在提交前处理。
- 用户输入 JSON 应拒绝未知字段，避免拼写错误静默回退。
- Host/Guest 本地状态写入使用项目的原子 JSON/目录发布函数，不直接覆盖规范协议文件。
- 新增路径必须通过 `resolve_under_root` 或等价验证，不能信任任务中的相对路径。
- 新增长任务必须接入停止令牌和 Job Object，不能只终止父进程。
- 修改 VMCI 协议时同步更新 C++ 验证、Schema、协议文档和端到端测试。

## 真实 VMware 测试

真实目标默认不存在，避免普通 `ctest` 误操作用户 VM。只能对专用实验 VM 启用，并提供明确确认字符串与
真实配置：

```powershell
cmake -S . -B build\real -DSATSUMA_ENABLE_REAL_VMWARE_SMOKE=ON -DSATSUMA_REAL_LAB_CONFIG=D:\lab.local.json -DSATSUMA_REAL_VM_ID=vm_01 -DSATSUMA_REAL_SNAPSHOT=clean -DSATSUMA_REAL_VMWARE_CONFIRM=I_UNDERSTAND
cmake --build build\real --config Release --target SatsumaRealVmwareSmoke
```

Host/Agent 强制终止测试由 `SATSUMA_ENABLE_REAL_VMWARE_CRASH_RECOVERY` 控制。确认字符串、超时和目标必须按
CMake Cache 描述显式提供。VMCI 断线恢复应在专用实验 VM 中通过停止/重启 Host 网关验证；不要对包含未保存
工作或唯一证据的 VM 运行这些目标。

## CI 与发布检查

Windows CI 对每次 push/PR 执行：Schema 校验、Debug 构建测试、Release 构建测试和 UTF-8 ZIP 打包。准备发布时
还应在本机完成：

1. `SatsumaHost --help`、`SatsumaVM --help` 和 `--version` smoke。
2. 检查 `output` 展开目录和 ZIP 中不存在测试工具、机器绝对路径或已填写的本机配置。
3. 对专用 VMware 环境执行一次最小 `check`、`run`、`report`。
4. 检查 `更新日志.md`、`第三方声明.md`、版本号和许可证状态。
5. 运行 `git diff --check`，确认没有编码、换行或无关整文件变化。
